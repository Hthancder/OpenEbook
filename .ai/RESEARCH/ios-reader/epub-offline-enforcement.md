# EPUB offline enforcement for Readium 3.11.1
**Ngày:** 2026-11-21 · **Nguồn chính:** Official Readium Swift Toolkit 3.11.1 source/docs and Apple WebKit API documentation; design research only.
**Trạng thái:** done (source research only; offline EPUB remains unverified) · **Câu hỏi:** Can native HTTPClient implementation fail closed for all remote loads while local FileURL reader works? What protocol methods are required in pinned 3.11.1? What are WKContentRuleList pre-load coverage and limitations for http/https, ws/wss, data iframe scripts initiating network, external navigation/custom schemes? What safe policy options are already public? Define product-safe minimal implementation and verification plan without enabling EPUB until first-load no-outbound is proven.

## Bottom line

A rejecting public `HTTPClient` can stop every request routed through that native Readium client while `FileResourceFactory` continues to read local files. It cannot stop WebKit's independent networking. The pinned navigator's public user-content hook runs after first-load initiation; expanding the current rule to WS(S) does not repair that ordering. The public opener/container transform can install a structural first-head CSP before HTML/XHTML author bytes are served, and that CSP can govern remote CSS subfetches, but it does not provide a universal policy for standalone SVG, all automatic navigation, or every egress channel. Keep EPUB gated: no source-level full-product offline guarantee or runtime zero-egress result was established; a narrower rendering policy or a pre-load/header/navigation upstream change requires an explicit decision, not a silent bypass.

## Findings

### Confirmed pinned native and first-load boundaries

- Tag `3.11.1` resolves to commit `9a8c094b72245fd27043c9d298005e5c78b32a01` in the official source tree. Source: https://api.github.com/repos/readium/swift-toolkit/git/trees/3.11.1?recursive=1
- `HTTPClient: Loggable` requires exactly one HTTP method: `func stream(request: HTTPRequestConvertible, consume: @escaping (_ chunk: Data, _ progress: Double?) -> HTTPResult<Void>) async -> HTTPResult<HTTPResponse>`. Fetch/download helpers are protocol extensions. A rejecting implementation can return `.failure(.security(OfflinePolicyError.remoteAccessDenied))` immediately, never call `consume`, never create a session, and never forward to `DefaultHTTPClient`. This is real failure, not a success/no-op. Sources: https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Shared/Toolkit/HTTP/HTTPClient.swift#L13-L46 and https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Shared/Toolkit/HTTP/HTTPError.swift#L10-L60

Therefore denying this client is compatible with the native local-file retrieval path, not proof about WebKit traffic. Sources: https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Shared/Toolkit/Data/Resource/ResourceFactory.swift#L20-L35 and https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Shared/Toolkit/File/FileResourceFactory.swift#L10-L20

### Apple/WebKit enforcement coverage and limitations

1. **Rules are a resource-load filter, not a device firewall.** Apple describes `WKContentRuleList` as a compiled set of rules modifying how a webpage loads content; its syntax is the Safari content-blocker syntax. `block` stops loading a matching resource; omitting `resource-type` matches all supported resource types. The current documentation includes `document`, `image`, stylesheet/script/font/media, `fetch`, `websocket`, and others. Use a URL trigger `^(https?|wss?):` with no resource-type/first-party/third-party restriction, rather than `^https?`, for HTTP(S) plus WS(S) defense in depth. This fixes the obvious scheme gap, not the callback timing defect. Current Apple docs do not by themselves prove every subtype or speculative networking path on every iOS 15 point release. Sources: https://developer.apple.com/documentation/webkit/wkcontentrulelist ; https://developer.apple.com/documentation/safariservices/creating-a-content-blocker ; historical upstream change for fetch/websocket/other resource types: https://bugs.webkit.org/show_bug.cgi?ctype=xml&id=222709 (filed 2021-03-03, resolved FIXED; this is source history, not an app runtime pass).
2. **Pre-load configuration must precede load.** Compile the list successfully before creating/loading the consuming web view; add it to `WKUserContentController`, assign that controller to `WKWebViewConfiguration`, and construct the web view with the configuration. Apple says the initializer copies the configuration, so mutating the original configuration later has no effect. The content-controller API supports adding rule lists, but it promises no retroactive cancellation or rollback of already-started requests. Readium's hook adds to the live controller after `load` initiation, so it cannot establish first-load protection. Sources: https://developer.apple.com/documentation/webkit/wkwebview/init(frame:configuration:) ; https://developer.apple.com/documentation/webkit/wkusercontentcontroller/add(_:) ; pinned ordering links above.
3. **`WKURLSchemeHandler` only handles schemes WebKit does not already handle.** `WKWebViewConfiguration.setURLSchemeHandler(_:forURLScheme:)` raises an exception when registering a native scheme such as HTTPS. A `readium:` handler can confine its own archive lookups; it cannot intercept arbitrary `http:`, `https:`, `ws:`, or `wss:` requests by claiming the custom-handler API. Do not use private scheme registration, swizzling, or a URLProtocol interception claim as a substitute. Sources: https://developer.apple.com/documentation/webkit/wkurlschemehandler ; https://developer.apple.com/documentation/webkit/wkwebviewconfiguration/seturlschemehandler(_:forurlscheme:)
4. **Readium's native client and WebKit are separate request paths.** The pinned navigator creates its own internal `WebViewServer(scheme: "readium")`; it does not feed all browser networking into the injected native HTTP client. Publication resources with no remote base URL are served through `publication.get(href)`, then Readium CSS is injected. Require an archive-backed publication with no remote base URL; if `publication.baseURL` exists, the pinned view model uses it directly as the publication base. Sources: https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Navigator/EPUB/EPUBNavigatorViewModel.swift#L45-L79 and #L169-L195
5. **External navigation needs its own denial, including custom schemes.** Readium's `NavigatorDelegate.navigator(_:presentExternalURL:)` default calls `UIApplication.shared.open`. Override it to present a genuine offline-policy denial and never hand off to Safari, URL handlers, or another application. But pinned spread navigation policy intercepts only `.linkActivated`; other navigation types default to `.allow`. Therefore that public callback alone does not cancel script-driven `location=`, meta refresh, forms, redirects, child-frame navigation, or automatic custom-scheme navigation. Sources: https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Navigator/Navigator.swift#L113-L138 ; https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Navigator/EPUB/EPUBSpreadView.swift#L651-L668
6. **A data URL does not itself contact the network, but content inside it can.** A rule matching only the outer HTTP scheme is not a policy for whether data/srcdoc/blob frames may exist or run script. Requests those documents generate need enforcement at their destination, plus a policy preventing active embedded documents. Cover `iframe src=data:`, `srcdoc`, blob/worker creation, SVG active content and event handlers explicitly in fixtures. CSP `connect-src 'none'` is intended to deny script network connections including WebSockets; `frame-src 'none'`, `object-src 'none'`, and `worker-src 'none'` deny those active nesting contexts. These controls are not substitutes for preventing untrusted scripts and navigation. Standards source: https://w3c.github.io/webappsec-csp/#directive-connect-src and #directive-frame-src ; WebKit CSP overview: https://webkit.org/blog/6830/a-refined-content-security-policy/
7. **WebKit offers a useful native content-script switch, but Readium does not expose it at this boundary.** Apple `WKWebpagePreferences.allowsContentJavaScript = false` (iOS 14+) disables content-referenced JavaScript including inline scripts and `javascript:` URLs. It is preferable to JavaScript monkey-patching when the owner can set it before navigation, while validating Readium's app-injected scripts still work. Pinned public EPUB configuration/hook does not supply `WKWebViewConfiguration` or `WKWebpagePreferences`; the internal spread owns navigation delegation. A consumer cannot claim this switch is installed by merely receiving `WKUserContentController`. Source: https://developer.apple.com/documentation/webkit/wkwebpagepreferences/allowscontentjavascript ; pinned EPUB configuration and spread initialization: https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Navigator/EPUB/EPUBNavigatorViewController.swift#L47-L125 and https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Navigator/EPUB/EPUBSpreadView.swift#L74-L104

### Public resource transformation: real option, bounded coverage

- The public opener `onCreatePublication` hook has type `Publication.Builder.Transform = (_ manifest: inout Manifest, _ container: inout Container, _ services: inout PublicationServicesBuilder) async -> Void`. It explicitly permits wrapping the root container. `TransformingContainer(container:transformer:)` accepts `ResourceTransformer = (_ href: AnyURL, _ resource: Resource) -> Resource`. `TransformingResource.init(_:transform:)` accepts `((ReadResult<Data>) async -> ReadResult<Data>)?`. These are real pinned public APIs, not a proposed fork. `TransformingResource` buffers full resource content, so enforce the existing resource/decoded-size bounds before parsing/rewriting. Sources: https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Shared/Publication/Publication.swift#L191-L225 ; https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Shared/Toolkit/Data/Container/TransformingContainer.swift#L9-L43 ; https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Shared/Toolkit/Data/Resource/TransformingResource.swift#L9-L45
- **For validated HTML/XHTML, a first-head CSP can precede hostile author bytes without using the late delegate.** Decode strictly with bounded input, use the existing structural parser appropriate to the actual media type, create the HTML-namespace meta element as the first policy-bearing child of a valid head, serialize deterministically, and only then serve bytes. Reject malformed/ambiguous encodings and parse failures rather than falling back to original data. Do not regex-rewrite XML/HTML/CSS. Verify MIME/namespace/serializer behavior for XHTML, not just text/html. Normative CSP delivery: https://w3c.github.io/webappsec-csp/#meta-element ; pinned transform path: https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Navigator/EPUB/EPUBNavigatorViewModel.swift#L169-L178
- **Meta CSP is not a universal EPUB envelope.** It does not protect content before the meta; `sandbox`, `frame-ancestors`, and reporting directives are unsupported in meta. It does not establish a trustworthy policy for an arbitrary top-level SVG document by inserting an SVG or misplaced HTML meta node. CSS is not an HTML document into which this policy can be injected, and nested documents must inherit an effective policy or carry their own verified policy. Do not assert that a meta added to XHTML automatically covers every SVG document, direct SVG spine entry, stylesheet subfetch, refresh or custom-scheme navigation. Source: https://w3c.github.io/webappsec-csp/#meta-element ; WebKit HTML meta processing passes whether the meta is under `document->head()`: https://github.com/WebKit/WebKit/blob/main/Source/WebCore/html/HTMLMetaElement.cpp#L182-L191 (current source corroboration, not a pinned iOS 15 guarantee).
- **The public Resource wrapper cannot add response headers to this server.** Pinned internal `WebViewServer.respond` builds a fixed header dictionary (length/ranges/content type, optional CORS), then makes `HTTPURLResponse`. There is no public policy-header callback; arbitrary `ResourceProperties` are not copied into HTTP response headers. `Content-Security-Policy` response headers would be the appropriate pre-parser mechanism across HTML/SVG, but using them here requires an upstream/public hook or an approved maintained change. Source: https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Navigator/EPUB/WebViewServer.swift#L290-L356
- Readium injects its own CSS **after** `publication.get` returns the wrapped resource, only for declared HTML and reflowable layout; it can put local assets ahead of an injected CSP. Verify the final served bytes and use only packaged `readium:` assets, never authorize external URLs just to make the reader work. Fixed layout also creates an internal wrapper with `loadHTMLString` and then loads spine resources into it, so test both wrapper and child documents. Sources: https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Navigator/EPUB/EPUBNavigatorViewModel.swift#L310-L349 ; https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Navigator/EPUB/EPUBFixedSpreadView.swift#L20-L62

**Conclusion on the parent-proposed route:** native deny-client plus structural first-head CSP is a legitimate public-API hardening route for a strictly validated HTML/XHTML rendering subset, not currently a source-level zero-egress guarantee for the full requested EPUB product. Enabling all DRM-free EPUB on this evidence would exceed what was established. No fork, narrowed format support, or disabling existing reading behavior is authorized by this report.

## Recommendation / change disposition

### Recommended minimal implementation interfaces (proposal only)

1. **Native request denial, no forwarding.** Reuse one `OfflineHTTPClient: HTTPClient` for the current `AssetRetriever(httpClient:)` and `DefaultPublicationParser(httpClient:assetRetriever:pdfFactory:)` wiring. Required method body returns a typed denial immediately. Do not treat a denied request as empty success, retry it through the default client, or suppress it into valid book data. `HTTPClient` inherits instance/static `Loggable.log` requirements, both supplied by its public default extension; no additional HTTP method is required. The following is a signature-level implementation proposal, NOT compiled evidence:

```swift
private enum OfflinePolicyError: Error {
    case remoteAccessDenied
}

private struct OfflineHTTPClient: HTTPClient {
    func stream(
        request: HTTPRequestConvertible,
        consume: @escaping (_ chunk: Data, _ progress: Double?) -> HTTPResult<Void>
    ) async -> HTTPResult<HTTPResponse> {
        .failure(.security(OfflinePolicyError.remoteAccessDenied))
    }
}
```

   This implementation denies unconditionally because a Readium HTTP client is not the local-file reader. Do not create a URLSession, even for HEAD, redirect probing, MIME detection or a loopback exception. Source signatures: https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Shared/Toolkit/HTTP/HTTPClient.swift#L13-L46 ; https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Shared/Logger/Loggable.swift#L54-L80 ; file/HTTP factory separation above.

2. **Resource admission before navigation.** On the existing `PublicationOpener(... onCreatePublication:)` hook, validate the local archive manifest and wrap `container` with a membership-confining `Container` implementation, then `TransformingContainer`. Lookups must resolve only to canonical package entries: deny absolute remote/custom/file URLs, traversal/encoded aliases outside the package, and unexpected active document types. Do not dereference a URL merely to classify it. Preserve local media, images, CSS, fonts, fragments and required metadata when accepted. This is a proposed policy on the public `Container.entries` / subscript interface, not something `TransformingContainer` automatically enforces. The protocol and why a transformed container has no direct `sourceURL`: https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Shared/Toolkit/Data/Container/Container.swift#L9-L28

3. **Conditional HTML/XHTML hardening, not full EPUB authorization.** A public resource wrapper can return an actual decoding/access failure before serving any author bytes, or return structurally rewritten bounded bytes. Proposed CSP for an explicitly approved static HTML/XHTML policy would start from:

```text
default-src 'none';
connect-src 'none';
script-src 'none';
style-src readium: 'unsafe-inline';
img-src readium: data:;
font-src readium:;
media-src readium:;
frame-src 'none';
child-src 'none';
worker-src 'none';
object-src 'none';
base-uri 'none';
form-action 'none'
```

   This is a candidate to verify, not a drop-in proven configuration. It deliberately forbids author scripts, active frames/objects, remote CSS/fonts/images/media and form submission, while allowing packaged reader CSS/fonts and inline book styling. Permit `data:` only for demonstrably passive image use, not for scripts, frames, objects, or navigation. Do not add `script-src readium: 'unsafe-inline'` to accommodate unknown failures: that would also trust author scripts served under the same scheme. Validate Readium selection/layout/locator/search behavior under `script-src 'none'`; native `WKUserScript`/evaluate calls and page-referenced scripts are different paths, but compatibility was not run here. Explicit local origin/path restrictions should be tighter where WebKit's custom-scheme matching permits; `readium:` is a scheme-wide allow, not an archive membership check. The membership-confining container must remain. CSP source semantics: https://w3c.github.io/webappsec-csp/#directives ; Apple content-script distinction: https://developer.apple.com/documentation/webkit/wkwebpagepreferences/allowscontentjavascript

   Independently reject or structurally remove author navigation mechanisms such as refresh directives, base URL rewriting and resource hints (`dns-prefetch`, `preconnect`, `prefetch`, preload/modulepreload), with an explicit compatibility decision. For XHTML/XML, inspect the prolog too: an `xml-stylesheet` processing instruction precedes any head meta and can name a remote stylesheet. Reject unsupported processing instructions or transform them under an explicit bounded XML policy before serving bytes; rejecting external entities alone does not handle this path. Official definition: https://www.w3.org/TR/xml-stylesheet/ . Meta CSP is not a universal navigation/DNS/WebRTC firewall. Existing offline-only product scope does not authorize silently turning arbitrary EPUB into a restricted new format or discarding substantive content. In particular, reject-to-safe-error is a security result, not a passing EPUB-reader acceptance test. Source of CSP meta limits: https://w3c.github.io/webappsec-csp/#meta-element ; current WebKit speculative load implementation (corroboration only): https://github.com/WebKit/WebKit/blob/main/Source/WebCore/loader/LinkLoader.cpp

4. **External handoff denial.** Implement the exact public `navigator(_ navigator: Navigator, presentExternalURL url: URL)` callback. Surface the existing policy error to the user; never call `UIApplication.open`, launch Safari, or auto-allow custom schemes. Do not install a new UI action that cannot work. This catches the link-activation path, not every automatic navigation; keep that distinction in review and fixtures. Source: https://github.com/readium/swift-toolkit/blob/3.11.1/Sources/Navigator/Navigator.swift#L113-L138

5. **Keep EPUB gates closed until the whole boundary is solved.** The minimal native denying client is safe to propose now, but not sufficient to authorize enabling ImportService/ReaderHostView EPUB. Full current product support needs a pre-initial-load WebKit policy boundary, including every document type it renders, and navigation coverage. The pinned public navigator cannot supply all of that via the existing hook. If public structural transforms cannot demonstrably cover an existing supported book type, the decision is not to guess or silently narrow scope: obtain approval for an upstream hook / minimal maintained patch or fork, or for a precisely stated support restriction. Any fork/patch proposal must name its maintenance consequence and separately request approval before adoption. This report grants neither. The relevant missing capability is access before `WebView(configuration:)`/`load`, plus response CSP or equivalent document policy and complete navigation decisions, not another late user script. Sources: pinned constructor/hook/response/default-navigation code above.

### Positive/negative fixture and network-observer smoke plan

This is a future acceptance plan, NOT work executed in this research assignment. It does not require a new production package. Fixture-only hostile code belongs in explicit test artifacts, never in reader implementation. All negative probes use investigator-controlled endpoints, no third-party tracking or real credentials.

**Observer setup and evidence validity**

- Use a clean first launch, fresh book identity, empty relevant WebKit caches, and no cached DNS/HTTP result for unique per-case hostnames. Start capture before import/preflight/opener construction, not after the first page is visible; stop after first display, neighboring preloads, interactions and reopen. Run with working network connectivity. Airplane-mode success is supplementary usability evidence only.
- Record a device-wide packet trace and correlate the exact book/case/time with observer-controlled DNS, HTTP(S), WS(S), TLS handshake/connection and UDP logs. On a physical iOS device use Apple's supported Remote Virtual Interface workflow from a Mac when available; on Simulator capture the applicable Mac interfaces and account for shared system traffic. Gateway capture on an isolated test network is an additional independent observer. Apple explains that packet traces record traffic on the selected interface and documents the iOS capture workflow: https://developer.apple.com/documentation/network/recording-a-packet-trace
- Prove the observer before and after a run using separate deliberate positive-control requests to each endpoint class. For browser probes, demonstrate that the exact fixture channel can contact the endpoint under otherwise equivalent WebKit/ATS/TLS/network conditions in an isolated non-production control harness. Never introduce a release-app bypass or weaken production protection for this control. ATS denial, CORS error after a request, TLS failure, DNS failure, an unavailable server, and a failed WebSocket handshake must not be misreported as offline enforcement. If a channel's positive control cannot be observed, that channel remains unverified.
- HTTP request logs alone are insufficient: observe DNS questions, TCP/TLS/QUIC connection attempts and WS handshakes, plus STUN/TURN/UDP for script probes. A CORS failure does not establish zero network traffic. Include both hostnames and direct IPv4/IPv6 destinations so a DNS-only observer cannot yield a false pass. Distinguish unrelated OS background traffic from fixture endpoints using unique labels, destination/time correlation and a documented baseline. Do not simply subtract unexplained book-correlated traffic.
- Save artifact hashes, exact commit, resolved Readium commit, IPA hash, OS/device model, network setup, capture start/end, fixture hash, expected outcome, actual visual/error state, endpoint logs and pcap. No credentials or unrelated personal payloads in distributed evidence. A screenshot documents behavior, not absence of requests.
